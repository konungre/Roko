# AI-DSL composition search in durable v2 conversation

An optional cognitive task has this exact data shape:

```json
{"component":"ai_dsl","request":{"version":1,"goal":"speech_emotion","depth":4}}
```

Goals are `speech_to_text`, `bytes_to_text` and `speech_emotion`; depth is an
integer 0..4. The existing three-task limit remains. `ai_dsl` is optional in
learning profiles; profiles qualified only for MetaMo/AIRIS/NACE remain valid.
An unqualified AI-DSL request fails closed. `qualify_learning.py` accepts the
optional `--ai-dsl-manifest` generated by the local AI-DSL gateway preparation.
All source and native runtime closure pins remain required.

The separate controller executes original upstream AI-DSL code on actual
Hyperon. The independent checker verifies composition signatures, proof depth
and required service membership. A compact observation tells the model how many
plans were accepted/rejected and explicitly says no service ran. Complete proofs,
pipelines, rejection reasons and `executed_services: 0` are returned in
`cognitive_results`. They participate in request identity and commit atomically
with history and the cognitive ledger. Saved replay skips search and inference.

`tests/probe_ai_dsl_native.py` runs the actual chain: AI-DSL search, Omega/PeTTa
dispatch, supervised MeTTa-Motto and native Granite. It checks exact structured
results, atomic observation/history, changed-payload conflict, and restart replay
with zero native calls. A native search is computed here; speech recognition,
emotion recognition, external services and actions are never executed. Model
prose remains advisory. The native answer in the first qualification accurately
reported one accepted and one rejected plan and that no service ran.
